# 五分钟零 API 费用演示稿

适用范围：当前工程阶段，不需要 DeepSeek Key。模型决策由固定脚本替代，Docker、工具执行、补丁生成和独立验证仍实际运行；演示结果不能当作模型修复成功率。环境准备需要下载依赖和镜像，提前完成。

## 演示前准备

在仓库根目录执行一次：

```bash
make setup
docker pull python:3.11-slim
PYTHONPATH=src .venv/bin/python -m repofix doctor
```

启动工作台：

```bash
make serve
```

打开 `http://127.0.0.1:8765`。若服务已经启动，直接使用原页面；端口被占用时先确认占用来源。演示只选择平均值任务和“固定脚本演示”。

## 现场操作与讲解

| 时间 | 操作 | 可以直接使用的讲解 |
|---|---|---|
| 0:00–0:30 | 展示任务与运行方式 | “这是 Python Issue 修复 Agent 的工程原型。本次使用固定脚本替代模型，不发起 API 请求，展示实际的工具执行和验收流程。” |
| 0:30–1:30 | 提交平均值任务，查看执行轨迹 | “控制器先冻结代码、复现失败，再执行工具。真实模式下，下一步工具及参数由 DeepSeek 根据此前结果选择；今天这个序列提前固定。” |
| 1:30–2:15 | 打开代码补丁 | “错误是平均值分母使用了长度减一，单元素会除零。补丁修改生产代码，最终单独检查已有测试和配置是否被改动。” |
| 2:15–3:15 | 展示独立验证和原有回归 | “候选补丁会应用到冻结提交的另一份干净副本。三个独立用例通过，原有一项回归也通过。通过只代表这些用例覆盖的范围。” |
| 3:15–4:00 | 查看费用与轨迹产物 | “这次 provider 是 scripted-demo，实际模型请求为零。真实模式会记录服务端 usage，并在请求前预留预算；超时等不明状态保留预留，不自动付费重试。” |
| 4:00–5:00 | 结合架构图说明边界 | “模型负责选择动作，工具在 Docker 中运行，控制器负责预算、停止和验收。现阶段已验证系统流程，真实模型效果和四组配置对照仍待实测。” |

不要把演示响应轮数称为真实 API 请求数，也不要把参考补丁验证成功率称为 Agent 成功率。先讲清一次修复闭环，再按追问展开队列、SSE 和恢复机制。

## CLI 备用演示

页面异常时从同一仓库执行以下命令，仍不调用模型：

```bash
make demo
```

命令输出中的 `output` 是本次运行目录。按该目录打开 `report.json`、`patch.diff` 和 `trace.jsonl`；不要选择目录名排序后猜测哪份是当前结果。

需要确认的报告字段：

| 字段 | 当前脚本演示的期望 |
|---|---|
| `provider` / `evidence_type` | `scripted-demo` / `scripted` |
| `resolved` / `has_patch` | 均为 `true` |
| `verification` | `passed` |
| `regression.status` | `passed` |
| `request_reservations` / `estimated_cost_rmb` | 均为 `0` |

如果 Docker 预检失败，先处理环境问题；保留失败报告。可以说明历史截图的来源，但不要将旧截图说成现场执行结果。完整诊断见 [运行手册](runbook.md)。

## 额外展示：恢复而不重复执行

有时间时单独执行：

```bash
PYTHONPATH=src .venv/bin/python scripts/resume_smoke.py
```

脚本在完整第一轮后停止，再恢复相同任务，检查总工具调用为 4 次、脚本响应为 5 次。它证明已完成轮次可继续；在途状态不明确时程序拒绝重放，并不保证任意崩溃时都恰好执行一次。
