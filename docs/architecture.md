# 架构与设计取舍

## 模块

| 文件 | 职责 |
|---|---|
| `context.py` | 保留工具调用配对的历史输出压缩 |
| `tools.py` | Docker 内结构化代码工具与参数校验 |
| `agent.py` | 模型—工具循环，参数检查、步数和上下文限制、轨迹写入 |
| `provider.py` | DeepSeek HTTP 适配与明确标记的 scripted demo |
| `sandbox.py` | 一次性 Docker 容器与超时清理 |
| `workspace.py` | 原仓库快照、Git 补丁、干净副本与测试完整性检查 |
| `evaluation.py` | 独立 unittest 执行、原有用例回归门禁与结果分类 |
| `preflight.py` | 付费调用前检查依赖导入、测试收集与原版本失败 |
| `budget.py` | SQLite 事务预留与 usage 结算 |
| `benchmark.py` | 任务清单校验、预算共享与分类型批量汇总 |
| `api.py` / `jobs.py` | 本地异步接口、SQLite 队列、事件日志与幂等控制 |
| `runs.py` | 可复用任务生命周期、结果报告与执行指纹 |
| `cli.py` | CLI 参数与配置入口 |

## 为什么先使用一个 shell 工具

先建立可复现的简单基线，允许模型自由使用目录浏览、文本搜索、Python 编辑和测试命令。后续可以引入结构化搜索、按行读取、补丁工具，比较它们是否改善成功率或降低 token，而不是预先认定工具数量越多越好。

## 为什么暂不引入框架

核心循环足够小，显式保留消息与调用结果，便于理解 tool_call_id 配对、观察异常和修改策略。未来根据持久化工作流需求决定是否引入框架。

## 当前限制

没有真实 DeepSeek 集成结果和 benchmark 成绩；没有自动依赖构建、语义索引、语义上下文摘要、Agent 断点恢复；当前提供本地单线程任务队列及工作台。验证进程通过临时缓存前缀避免读取仓库中的陈旧/损坏字节码。当前只支持 unittest；pytest 和自定义评测协议需要后续适配。已有测试及配置的补丁检查依赖常见命名规则；独立测试运行在同一解释器内，尚不能对抗恶意 monkey patch 或伪造结果输出。

预算账本记录已估算费用和未结算预留，保证多个进程预留时串行检查。估算并不构成供应商硬性计费保证。使用不同账本目录会分开计数。当前不自动重试，以免网络失败造成重复计费。
