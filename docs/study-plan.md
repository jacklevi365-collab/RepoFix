# 七天代码理解与面试准备

当前先不配置 API Key。本计划的目标是独立运行、解释和修改现有项目，不新增付费实验，也不为凑技术栈扩展功能。每天先按自己的话讲解，再对照代码纠正；每项保留一份个人笔记。

| 天数 | 阅读和动手 | 当天完成标准 |
|---|---|---|
| 第 1 天 | 按演示稿运行脚本任务，阅读 `agent.py`、`provider.py` | 画出一轮消息、工具调用、结果返回的顺序；明确脚本与真实模型的区别 |
| 第 2 天 | 阅读 `tools.py`、`sandbox.py`、`workspace.py` | 从一次工具参数跟到容器命令；解释路径检查、冻结副本、镜像身份与 Docker 的局限 |
| 第 3 天 | 阅读 `preflight.py`、`evaluation.py`、`runs.py` | 从报告解释原始失败、独立验证与已有回归；说明零测试为什么不能算成功 |
| 第 4 天 | 阅读 `budget.py`、`checkpoint.py`，运行恢复脚本 | 解释预留与结算、超时为何不直接重试、恢复为什么拒绝在途状态 |
| 第 5 天 | 阅读 `jobs.py`、`api.py` 和前端提交逻辑 | 讲清 HTTP 提交、幂等键、后台执行、SQLite 事件及 SSE 断线续读的关系 |
| 第 6 天 | 阅读 `context.py`、`benchmark.py`、`experiments.py` | 能解释四组实验只改变哪些因素、失败如何计入，以及为何还不能声称优化有效 |
| 第 7 天 | 脱稿演示一次，按面试问题自问自答 | 五分钟讲完闭环；能从代码定位三个追问，知道哪些效果仍未验证 |

所有文件位于 `src/repofix/`。目录结构和设计见 [架构说明](architecture.md)，现场操作见 [演示稿](demo-walkthrough.md)，问题列表见 [面试讲解](interview.md)。

## 三个不依赖模型的理解练习

1. 阅读 `examples/tinybug/repo` 和对应 `verification`，手算单元素、负数和空列表的预期结果，再对照独立验证报告。解释为什么演示通过不代表其他仓库也能修复。
2. 打开一次运行的 `trace.jsonl`，挑出一条工具调用，找到其参数、执行输出和下一轮输入；把能从轨迹证明的事实与脚本提前决定的动作分开写。
3. 在纸上推演“API 已发送但本地超时”和“完整轮次已落盘后进程退出”两个场景，分别说明预算和恢复应如何处理，再与实现对照。

这些练习不用伪造模型响应、不修改基准来源文件，也不需要改动现有测试来制造成功率。

## 投递前自查

- 能从干净终端启动并展示一次明确标注的脚本演示。
- 能解释自己的实现和协作方式，不将第三方源码量当作个人工作量。
- 简历中的每个数字都能对应验收报告或测试记录。
- 遇到没实测的问题明确说明当前证据范围，并能提出可执行的验证方法。
- 后续若配置 API，只按实验协议执行；现阶段不填模型成功率、成本下降或策略提升数字。
